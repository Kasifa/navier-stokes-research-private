## 1. 实际发现与修复复核

### B1（已关闭）：初版默认 Python 可在创建永久 claim 后、进入异常处理前失败

初版 `produce()` 先以独占模式创建 `RUN_CLAIM.json`，随后用 `shlex.join(sys.orig_argv)` 填写它；此时尚未建立 manifest，也未进入 `try`。本机默认 `python3` 的实际只读查询给出以下字段：

```text
version major.minor.micro = 3.9.6
executable = /Library/Developer/CommandLineTools/usr/bin/python3
hasattr(sys, "orig_argv") = False
```

查询只执行 `import sys`、打印 `sys.version`、`sys.executable` 和上述属性检查，没有导入生产器。初版 shebang 为 `/usr/bin/env python3`，`preflight()` 也未检查这个属性或最低 Python 版本。因此按该默认入口执行时，`claim.open("x")` 已创建文件，字典求值却在访问 `sys.orig_argv` 时抛出 `AttributeError`，留下空 claim；没有失败 manifest，随后再次执行会被“目录非空”永久拒绝。

这不是积分误差，也不是所需的一次有界科学试验失败。启动前应检查明确的兼容运行时，并在建立不可重试 claim 前拒绝不支持的版本；启动记录所需数据也应先完成可失败的求值，或纳入可保存失败状态的处理范围。后端旧 packet 路径含 `zip(..., strict=True)`，但本生产器避开该路径，不能用它声称当前积分必定在 Python 3.9 执行另一处错误。B1 的实际证据是当前入口无条件读取不存在的 `sys.orig_argv`；选定 Python 3.10+ 为支持范围可直接排除它。

最终版本在 `preflight()` 和 `produce()` 开始处均调用 `require_supported_python()`，在任何 mkdir/claim 之前拒绝 Python<3.10。`launch_record()` 用 `getattr` 读取原始参数，回退时注明解释器标志未知；claim 序列化也提前完成，创建、写入、flush/fsync 进入单独异常处理。失败时向 stderr 输出结构化 `STARTUP_CLAIM_FAILED`，注明是否由本次创建部分 claim，且不改写另一进程的 claim。`main()` 将前置失败记录为 `STARTUP_REFUSED`、返回 2。

以上实际变更排除了已发现的启动链。根代理明确使用 bundled Python 3.12.14；本审查没有替它执行入口。错误文案仍以旧后端 `zip(strict=True)` 说明最低版本，这可理解为整体后端的保守兼容范围，但不能据此称当前生产会执行该旧 packet 路径。该说明文字不影响入口修复，不构成继续阻断。B1 已关闭；本次没有创建运行目录或 claim。

### B2（已关闭）：初版最终预算观测可能超限，而状态仍为完成

初版正常路径最后调用 `check_budget()`，随后把状态设为 `CANDIDATE_NODES_COMPLETE_NOT_NS_CERTIFIED`，再调用 `progress(..., force=True)`。该调用会序列化清单并输出进度。其后 `finally` 先关闭闹钟，再计算目录字节、调用 `save_manifest()`；后者更新 `wall_seconds` 和 `peak_process_rss_bytes`，但不据此重判完成状态。

因此最后的序列化或清理若令已观测峰 RSS 越过 256 MiB，或关闭闹钟后的落盘跨过 180 秒，最终 manifest 可以同时带有超预算的观测值和 COMPLETE 状态，函数仍返回 0。这是完成状态与预算合同不一致；它不同于“检查点只能在一次 C 扩展调用返回后发现超限”的一般监测范围。

最终版本正常主体完成后先标为 `CANDIDATE_DATA_VERIFIED_FINALIZING`。`finally` 的 `final_budget_observation()` 核实际墙钟、进程历史峰 RSS 和包含不完整块的实际节点档案字节；无超限且处于 FINALIZING 才可暂置 COMPLETE。原子清单写入及其文件 SHA 完成后，再取一次 `exit_observation`；任何已观测越界均由 `mark_final_budget_stop()` 改为 `BUDGET_STOP`，重新保存清单及哈希，返回非零。

这两次观测及状态转移已实际逐行复核，关闭了已发现的成功状态缺口。最终 stdout 带 `success_exit_budget_observation`，它是清单最终写入之后的观测，应随实际运行日志保留；清单中的第一次 final observation 不能冒充该后写入观测。预算语义为实际观测超限不得成功，未声称 OS 能预防任何瞬时超分配，亦未把终端输出之后无穷细分的报告成本当作已观测预算。失败清理可为保存 STOP 证据继续落盘，不能改回成功。B2 已关闭。

## 2. 固定物理对象、节点与完整频谱

`ROOT=HERE.parents[2]` 从当前目录定位到反向科学工作树，后端路径正确。`modes_list()` 按 `itertools.product(range(-8,9), repeat=3)` 排除零模，恰给字典序全谱 \(17^3-1=4912\) 个模式；负频率映射逐整数三元组查找，没有丢掉共轭半谱或零模歧义。

`SpectralSystem(scale=1, delta=0.1, grid=27, cutoff=8, viscosity=1, rho=1)` 与合同完全相同。后端的缩放系数因而恢复物理 \(\nu=1\) 和单位非线性系数。生产器显式填入 \(\pm e_1\mapsto e_2\)、\(\pm e_2\mapsto e_3\)、\(\pm e_3\mapsto e_1\) 的系数 1，不调用旧 packet 的 `initial_state/evolve`。这恰为原 \(a=2(\cos x_3,\cos x_1,\cos x_2)\)。

`for node in range(5121)` 为每个节点单独调用一次 `system.rhs(state)`，随后仅在 `node<5120` 时以 `1/2048` 做一次 RK4。步长是二进制精确数；时间索引采用整数分子和共同分母，没有累计浮点时间漂移。共 5120 步、5121 个节点、末时间 \(5120/2048=5/2\)。后端每步四次 RHS，加独立斜率共 \(4\cdot5120+5121=25601\) 次调用，没有复用 RK 中间级冒充节点斜率。

`initial_q` 覆盖整个 \((4912,3,2)\) 数组，除六个指定实分量外全零；节点零以 `np.array_equal(values[count], initial_q)` 核验整个数组。因规定六模横向且共轭，随后数学定义中的精确平均和 Leray 投影保持 \(c^0=a\)，不是容差初值。

## 3. Q52 编码和正式科学对象

`quantize()` 从全谱网格中按正确的模索引提取三分量，转成 `(mode, vector_component)` 后，分别用 `ldexp(part,52)` 与 `rint` 编码实部、虚部。规则明确为 nearest-ties-to-even。乘以二次幂、舍入后的结果先检查有限性，再要求严格 \(|Z|<2^{63}\)，然后才 `astype("<i8")`，避免了把 `float(int64_max)` 舍入成 \(2^{63}\) 后误放行的错误。

代码也拒绝可表示的下端点 \(-2^{63}\)，这是比 int64 本身更窄的保守拒绝范围，不是溢出放行。正式数组仍为小端 int64，所有实虚部的位数、轴顺序与量化分母都进入配置及块描述。Q52 是量化后正式数据，文稿和清单没有称其为未保存浮点阶段的无损副本。

精确参照是存档整数经
\[
c_k=P_k\frac{Z_k+\overline{Z_{-k}}}{2\cdot2^{52}},
\]
及同式独立斜率数组定义的有理场。`rational_reference_float()` 只是该定义的浮点诊断求值，明确不覆盖已保存整数。这里先把整数转为浮点再平均，仅适用于非严格诊断；未来精确验证仍必须在数学整数/任意精度整数中处理共轭取负和相加，并保留 \(|k|^2\) 的有理投影分母。本代码没有实现这份连续验证，也没有误称已经实现。

每个节点斜率来自当时未量化生产状态的独立 RHS，所以一般不等于固化后的精确 \(\mathcal F_G(c^n)\)。其差异属于未来完整内带残差，当前标签与 C1 合同相容。

## 4. 块存储、共享节点与完整回读

两个固定 64 节点的值/斜率缓冲区流式写出，未把全部约 2.3 GiB 原始节点数组常驻内存。每个块保存共同节点索引、时间分子、时间分母、量化分母、值与斜率，含形状、dtype、原始数据 SHA 和压缩文件 SHA。切片保持 C 连续，`memoryview(...).cast("B")` 的字节哈希与小端数组一致。

`flush_block()` 要求首节点等于已存总数，末节点等于首节点加 `count-1`；成功后才增加已存数并清空计数。正常完成时是 80 个满块和最后 1 个单节点块，节点 0 至 5120 各一次。值、斜率各只存一份；跨块的 Hermite 段通过全局节点索引共享它们，不重算第二份接点斜率。

NPZ 写入临时 `.partial`，完成并 fsync 后更名。末尾逐块回读所有数组，核文件大小/SHA、数组名集合、形状/dtype/数据 SHA，并核每块的两个节点序列；总节点数、步数和 9 个诊断索引也核验。最小修订版还补上 `modes.npy` 的最终文件 SHA 复核，该增补已实际读到。没有把“成功压缩”当成完整回读通过。

源码与两份科学合同的实际文件 SHA、规范化 JSON 配置 SHA、Python/NumPy 路径与版本、平台、命令、线程环境都写入清单，结束前再核源码字节。checkout 信息明确只标识 HEAD，不声称工作树干净；未运行 git。实际科学源码 SHA 能区分未提交的生产器版本。

## 5. 35³ 全漏出和 27³ Frobenius 采样

诊断先对已存整数的规定参照近似求值，再按真实整数频率嵌入 35³。其频率代表是 \(-17,\ldots,17\)，完整容纳二次支持 \([-16,16]^3\)。`ifftn(35**3 * coefficients)` 与反向 `fftn(...)/35**3` 归一化相配。旋度与叉积顺序给 \(\mathbb P(v\times\operatorname{curl}v)=B(v,v)\)，随后仅施加完整 Leray 并清零均值，没有调用后端 masked 非线性或截回 \(G\)。

节点残差使用 \(d+|k|^2c-B(c,c)\)，内带和外带都保留。`r2` 平方使用 `k2**2`，即 \(|k|^4\)；全谱已经含共轭双方，不另乘 2。网格中的 \(G+G\) 外浮点噪声也计入近似范数，并单独记录最大值；没有以裁剪噪声伪造更小诊断。零模按数学定义设零，且所有诊断均标为浮点、非严格、非连续上界。

对 \(j=1,2,3\)，代码枚举无序多重指标 \(\alpha\)，乘入 \(j!/\alpha!\)，恰恢复全部有序导数的 Frobenius 平方。导数相位 \(i^j\prod k_i^{\alpha_i}\) 正确，向量分量求和完整。采用实部平方并另报虚部舍入偏差，是实值参照的浮点采样诊断，不是区间上界。27³ 格点最大值的标签明确说明不能代替全空间 \(M_j\)。

9 个固定节点没有覆盖 Hermite 段间残差；近似终点 \(A_{-1}\) 也不包含真实解误差证书。当前代码没有暗中把这些诊断接入全局结论。

## 6. 预算与异常恢复的准确范围

`ArchiveWriter` 在每次写入前检查当前位置加写入长度不超过剩余节点档案额度，包含 NPZ 头、压缩数据和目录写入；先前完整块与 `modes.npy` 的字节已扣除。新部分块也不能因写入而越过该剩余额度。这里 512 MiB 计的是节点档案文件，运行清单/claim 的小额元数据不属于 `archive_bytes`，不应把该字段误称整个运行目录的总磁盘占用。

180 秒用墙钟闹钟和检查点共同停止；RSS 取进程历史峰值，所以 FFT 或压缩释放后也能发现先前越界。正常循环、斜率、RK4、诊断组、压缩写入和最终回读之间都有检查。进度在 512 步节点或约 10 秒触发，压缩/回读期间也可触发，避免只在积分循环报告。

这些监测保证的目标是发现超限后拒绝成功，不是 OS 层阻止任何一次分配或 C 扩展调用短暂越过物理上限。代码没有安装预防式 RSS 限额，Python 信号也可能在 C 调用返回后处理。不能从小缓冲布局推定已测峰值，更不能预填预算 PASS。B2 修复后的最终写入/哈希后观测与该监测语义相符。

在受 `try` 保护的工作阶段，非有限节点/斜率、Q52 越界、RK4 非有限状态、预算异常和一般异常均失败停止。已完成块保留；未完成 `.partial` 明确不可作完整块使用。更名后但尚未进入清单的文件另列为未验证、未计数，不假装其已通过哈希回读。`computed_nodes` 与 `stored_nodes` 分开，待存缓冲不被宣称已经归档。没有自动重跑、放宽精度或扩大规模。

目录非空拒绝与独占 claim 也阻止并行重复启动；不可重试设计中，B1 修复已将版本拒绝移到 claim 前。极端外部强制终止或不可写磁盘不能保证最后清单落盘，已有原子 manifest、完整块、部分块和 claim 应按实际状态恢复审查，不能直接视为生产完成。
